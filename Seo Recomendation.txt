# **Complete SEO Guide for Next.js Websites**

If you're developing websites using **Next.js**, SEO (Search Engine Optimization) should be part of your application architecture, not something you add at the end.

We'll cover SEO from beginner to advanced level, including technical implementation in Next.js, Google indexing, local SEO, performance, structured data, social media previews, and modern AI search optimization.

The goal is to build a website that is:

- Discoverable by Google, Bing, and other search engines.
- Properly indexed and ranked for relevant keywords.
- Optimized for local and international searches.
- Fast, mobile-friendly, and accessible.
- Understandable to search-engine crawlers and AI search systems.
- Designed to generate organic traffic, enquiries, leads, and conversions.

## **1. Understanding all types of SEO**

SEO is not just adding keywords to page titles. It consists of several interconnected disciplines.

## **SEO ecosystem**

**Search Engine Optimization (SEO)**

Complete website visibility strategy

**On-page SEO**

Content, keywords, headings, metadata

**Technical SEO**

Crawling, indexing, rendering, performance

**Off-page SEO**

Backlinks, authority, brand mentions

**Local SEO**

Google Business Profile, local searches

**Content SEO**

Blogs, landing pages, topical authority

**International SEO**

Languages, regions, hreflang

**E-commerce SEO**

Products, categories, product schema

**Image & Video SEO**

Media discovery and optimization

**Mobile SEO**

Responsive experience and usability

**AI Search / GEO**

Visibility in AI-generated answers

### **What each type does**

| SEO type          | Primary objective                           |
| ----------------- | ------------------------------------------- |
| On-page SEO       | Optimize individual pages                   |
| Technical SEO     | Make the website crawlable and indexable    |
| Off-page SEO      | Build authority and trust                   |
| Local SEO         | Rank in location-based searches             |
| Content SEO       | Attract visitors through useful content     |
| International SEO | Target multiple countries and languages     |
| E-commerce SEO    | Rank products and product categories        |
| Image SEO         | Appear in image search                      |
| Video SEO         | Improve video discovery                     |
| Mobile SEO        | Optimize mobile search experience           |
| Programmatic SEO  | Generate useful pages at scale              |
| Semantic SEO      | Build topic relevance and context           |
| GEO / AI SEO      | Improve visibility in AI search experiences |

These categories overlap. For example, a location-specific service page needs on-page, technical, content, and local SEO together.

## **3. On-page SEO in Next.js**

On-page SEO is everything you optimize within an individual webpage.

For example, consider a solar installation website targeting Varanasi.

A page might target:

- Solar panel installation in Varanasi
- Residential solar systems
- Commercial solar installation
- PM Surya Ghar subsidy
- Solar panel prices in Varanasi

Each topic should have a relevant page, not just a collection of keywords on the homepage.

### **A. Title tag**

The title is one of the most important elements of a page's search appearance.

Example:

```
Solar Panel Installation in Varanasi |
Arpit Solar Shop
```

Next.js implementation:

```
// app/layout.tsx

import type { Metadata } from "next";

export const metadata: Metadata = {
  title: {
    default: "Arpit Solar Shop | Solar Solutions",
    template: "%s | Arpit Solar Shop",
  },
  description:
    "Explore residential and commercial solar installation solutions.",
};
```

For an individual page:

```
// app/services/page.tsx

import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Solar Panel Installation Services in Varanasi",
  description:
    "Explore residential and commercial solar installation services in Varanasi.",
};

export default function ServicesPage() {
  return <main>Solar Installation Services</main>;
}
```

### **B. Meta description**

A short description that summarizes the webpage.

Example:

```
Looking for solar panel installation in Varanasi?
Explore residential and commercial solar solutions,
system pricing and installation services.
```

Google may use this description or generate its own search-result snippet based on the query.

### **C. Heading hierarchy**

Use headings to establish the content structure.

```
<main>
  <h1>Solar Panel Installation in Varanasi</h1>

  <section>
    <h2>Residential Solar Systems</h2>
    <p>Content about residential solar solutions.</p>
  </section>

  <section>
    <h2>Commercial Solar Systems</h2>
    <p>Content about commercial solar solutions.</p>
  </section>

  <section>
    <h2>Solar Installation Process</h2>

    <h3>Site Survey</h3>
    <h3>System Design</h3>
    <h3>Installation</h3>
  </section>
</main>
```

Best practices:

- Have one clear primary H1 for the page.
- Use H2 for major sections.
- Use H3 for subsections.
- Make headings descriptive and natural.
- Don't insert keywords unnaturally.

### **D. URL optimization**

Prefer descriptive URLs.

| Bad URL           | Better URL                        |
| ----------------- | --------------------------------- |
| `/page?id=123`    | `/solar-installation`             |
| `/services/page1` | `/services/residential-solar`     |
| `/blog/post-45`   | `/blog/solar-panel-cost-in-india` |
| `/abc`            | `/commercial-solar-installation`  |

Use lowercase words, hyphens, and consistent URL structures.

### **E. Image SEO**

Images should have:

1. Descriptive filenames.
2. Appropriate alternative text (`alt`).
3. Compressed file sizes.
4. Responsive dimensions.
5. Modern image formats such as WebP or AVIF where appropriate.

```
import Image from "next/image";

export default function SolarImage() {
  return (
    <Image
      src="/images/residential-solar-installation.webp"
      alt="Residential rooftop solar panel installation"
      width={1200}
      height={800}
      priority
    />
  );
}
```

Use `priority` selectively for important above-the-fold images. Don't apply it to every image.

### **F. Internal linking**

Connect relevant pages to one another.

Example:

```
Homepage
  |
  ├── Residential Solar
  │      ├── Solar Subsidy
  │      ├── Solar System Pricing
  │      └── Installation Process
  |
  ├── Commercial Solar
  │      ├── Industrial Solar
  │      └── Commercial Pricing
  |
  └── Blog
         ├── Solar Panel Maintenance
         └── Solar Panel Cost
```

Internal links help users and search engines discover related content.

## **4. Technical SEO in Next.js**

Essential for production

Technical SEO ensures that search engines can discover, crawl, render, and index your website correctly.

### **A. Rendering strategies: SSR, SSG, ISR and CSR**

This is particularly important when developing with Next.js.

| Rendering | Meaning                         | SEO application         |
| --------- | ------------------------------- | ----------------------- |
| SSR       | Server-Side Rendering           | Dynamic pages           |
| SSG       | Static Site Generation          | Marketing pages         |
| ISR       | Incremental Static Regeneration | Blogs and product pages |
| CSR       | Client-Side Rendering           | Interactive dashboards  |

My recommended approach:

- Homepage: Static rendering.
- Service pages: Static rendering.
- Blog pages: Static rendering or ISR.
- Product pages: ISR where appropriate.
- Admin dashboard: Private, non-indexable.
- User-specific account pages: Private, non-indexable.

**Important:** CSR is not automatically bad for SEO. Google can render JavaScript, but server-rendering important content makes discovery and rendering more reliable.

### **B. Sitemap.xml**

A sitemap tells search engines which URLs you want them to discover.

Next.js supports automatic sitemap generation.

Create:

`app/sitemap.ts`

```
import type { MetadataRoute } from "next";

export default function sitemap(): MetadataRoute.Sitemap {
  const baseUrl = "https://www.example.com";

  return [
    {
      url: baseUrl,
      lastModified: new Date(),
      changeFrequency: "weekly",
      priority: 1,
    },
    {
      url: `${baseUrl}/services`,
      lastModified: new Date(),
      changeFrequency: "monthly",
      priority: 0.9,
    },
    {
      url: `${baseUrl}/about`,
      lastModified: new Date(),
      changeFrequency: "monthly",
      priority: 0.7,
    },
  ];
}
```

Your sitemap becomes:

```
https://www.example.com/sitemap.xml
```

For a large website, generate the sitemap dynamically from your database, including only canonical, indexable URLs.

Note: `priority` and `changeFrequency` are hints in the sitemap format, not ranking boosts in Google.

### **C. Robots.txt**

This controls which paths crawlers are allowed to access.

Create:

`app/robots.ts`

```
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: "*",
      allow: "/",
      disallow: [
        "/admin/",
        "/dashboard/",
        "/api/",
      ],
    },
    sitemap: "https://www.example.com/sitemap.xml",
  };
}
```

Output:

```
https://www.example.com/robots.txt
```

Remember: `robots.txt` is not a security mechanism and does not guarantee that a URL won't be indexed. Use authentication for private pages and `noindex` when appropriate.

### **D. Canonical URLs**

Canonical URLs tell search engines which URL represents the preferred version of a page.

For example:

```
https://example.com/solar
https://www.example.com/solar
https://example.com/solar?source=facebook
```

You should establish one preferred URL.

Next.js:

```
export const metadata = {
  alternates: {
    canonical: "/solar",
  },
};
```

Use a consistent domain, HTTPS, trailing-slash policy, and canonical strategy.

### **E. Redirects and 404 pages**

If you change a URL, redirect the old URL to its replacement.

```
// app/old-service/page.tsx

import { permanentRedirect } from "next/navigation";

export default function OldServicePage() {
  permanentRedirect("/services/solar-installation");
}
```

For pages that genuinely don't exist:

```
import { notFound } from "next/navigation";

export default async function Page() {
  const data = null;

  if (!data) {
    notFound();
  }

  return <div>Page content</div>;
}
```

Use correct HTTP status codes. Avoid redirecting every missing page to the homepage.

### **F. Structured data / Schema.org**

This is one of the most useful advanced SEO techniques.

Structured data helps search engines understand what your content represents.

Common schema types:

| Schema         | Application          |
| -------------- | -------------------- |
| Organization   | Company information  |
| LocalBusiness  | Local business       |
| Product        | Product pages        |
| Service        | Services             |
| Article        | Blog articles        |
| BlogPosting    | Blog posts           |
| BreadcrumbList | Navigation hierarchy |
| WebSite        | Website information  |
| Person         | Author profile       |
| Event          | Events               |
| VideoObject    | Video content        |
| JobPosting     | Job listings         |
| Course         | Educational courses  |

Example: Organization schema in Next.js.

```
// app/components/OrganizationSchema.tsx

export default function OrganizationSchema() {
  const schema = {
    "@context": "https://schema.org",
    "@type": "Organization",
    name: "Arpit Solar Shop",
    url: "https://www.example.com",
    logo: "https://www.example.com/logo.png",
    description: "Solar system installation services.",
  };

  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{
        __html: JSON.stringify(schema).replace(/</g, "\\u003c"),
      }}
    />
  );
}
```

Add this component to the relevant layout or page.

Only include factual information that is visible on the website and genuinely describes the organization. For a local business, use an accurate `LocalBusiness` subtype and verified address, contact information, and opening hours where applicable.

Structured data doesn't guarantee rich results or higher rankings.

## **7. Content SEO and Keyword SEO**

Content SEO focuses on creating content that answers what people are searching for.

### **A. Keyword research**

There are several types of keywords:

| Keyword type   | Example                                |
| -------------- | -------------------------------------- |
| Short-tail     | Solar panels                           |
| Long-tail      | Best solar panels for a 3BHK house     |
| Informational  | How do solar panels work?              |
| Commercial     | Best solar installation company        |
| Transactional  | Buy solar panels                       |
| Navigational   | Arpit Solar Shop                       |
| Local          | Solar installation near me             |
| Question-based | How much does a 5kW solar system cost? |

### **B. Search intent**

Understand why someone searches for a particular keyword.

| Intent        | User wants             | Page to create       |
| ------------- | ---------------------- | -------------------- |
| Informational | Learn something        | Blog/article         |
| Navigational  | Find a brand           | Homepage             |
| Commercial    | Compare options        | Comparison page      |
| Transactional | Purchase or enquire    | Service/product page |
| Local         | Find a nearby business | Location page        |

### **C. Topic clusters**

Instead of creating disconnected articles, build topic authority.

Example:

**Solar Energy Guide**

Pillar page

Solar Panel Types

Solar Panel Pricing

Solar Subsidy

Solar Installation

Solar Maintenance

Solar Battery Systems

Each supporting article links to the pillar page and relevant service pages.

A good content strategy includes:

- Keyword research.
- Search intent mapping.
- Content planning.
- Original research and expertise.
- Internal linking.
- Content updates.
- Content performance analysis.

Don't publish AI-generated articles in bulk just to target keywords. Content should offer genuine value and demonstrate real experience.

## **8. International SEO**

If your business serves multiple countries or languages, you need international SEO.

For example:

```
example.com/en/
example.com/hi/
example.com/fr/
```

You can use:

- Country-specific domains.
- Subdomains.
- Language-based subdirectories.

### **Hreflang**

Hreflang tells search engines about alternate language or regional versions of a page.

Next.js:

```
import type { Metadata } from "next";

export const metadata: Metadata = {
  alternates: {
    canonical: "/en/services",
    languages: {
      en: "/en/services",
      hi: "/hi/services",
      "en-IN": "/en-in/services",
    },
  },
};
```

Make sure alternate versions point to one another correctly and that each page has suitable canonical metadata.

For dynamic product pages, use `generateMetadata()`.

```
// app/products/[slug]/page.tsx

import type { Metadata } from "next";
import { notFound } from "next/navigation";

type Props = {
  params: Promise<{ slug: string }>;
};

async function getProduct(slug: string) {
  // Fetch product from your database or API.
  return null;
}

export async function generateMetadata({
  params,
}: Props): Promise<Metadata> {
  const { slug } = await params;
  const product = await getProduct(slug);

  if (!product) {
    return { title: "Product Not Found" };
  }

  return {
    title: `${slug} | Solar Products`,
    description: `Explore product details and specifications for ${slug}.`,
  };
}

export default async function ProductPage({ params }: Props) {
  const { slug } = await params;
  const product = await getProduct(slug);

  if (!product) notFound();

  return <main>{slug}</main>;
}
```

This is a structural example; in production, use actual product fields for the title, description, price, and availability.

## **10. Performance SEO and Core Web Vitals**

Website speed and user experience matter for both users and search visibility.

Google's Core Web Vitals measure three important areas:

## **Core Web Vitals**

**LCP – Largest Contentful Paint**

≤ 2.5 seconds

How quickly the main content appears.

**INP – Interaction to Next Paint**

≤ 200 ms

How quickly the page responds to interactions.

**CLS – Cumulative Layout Shift**

≤ 0.1

How much unexpected layout movement occurs.

These are Google's good-performance thresholds, measured at the 75th percentile of real-user visits.

### **Next.js performance optimization**

| Technique               | Benefit                              |
| ----------------------- | ------------------------------------ |
| `next/image`            | Image optimization                   |
| `next/font`             | Font optimization                    |
| Server Components       | Reduce unnecessary client JavaScript |
| Dynamic imports         | Load code when needed                |
| Lazy loading            | Delay offscreen media                |
| Caching                 | Reduce repeated server work          |
| CDN                     | Improve content delivery             |
| Code splitting          | Reduce initial JavaScript            |
| Proper image dimensions | Reduce layout shifts                 |
| Avoid excessive scripts | Reduce performance overhead          |

Example:

```
import dynamic from "next/dynamic";

const HeavyComponent = dynamic(
  () => import("@/components/HeavyComponent"),
  {
    loading: () => <p>Loading...</p>,
  }
);
```

Measure actual performance using Google PageSpeed Insights and Chrome Lighthouse rather than assuming that using Next.js guarantees good scores.

## **12. Programmatic SEO**

This is an advanced technique particularly useful for websites with many products, services, or locations.

Instead of manually creating every page, you generate pages from structured database content.

Example database:

| City     | Service           | Slug                       |
| -------- | ----------------- | -------------------------- |
| Varanasi | Residential Solar | residential-solar-varanasi |
| Jaunpur  | Residential Solar | residential-solar-jaunpur  |
| Ghazipur | Residential Solar | residential-solar-ghazipur |

Next.js route:

```
app/
  services/
    [slug]/
      page.tsx
```

Your application retrieves the relevant content from a database and generates the page.

Suitable technologies:

- Next.js dynamic routes.
- Supabase/PostgreSQL.
- CMS.
- Static generation or ISR.
- Dynamic metadata.
- Dynamic sitemap generation.

**Warning:** Programmatic SEO is not about generating thousands of thin, duplicate pages. Every published page should provide unique, useful information.

## **13. GEO – Generative Engine Optimization / AI Search**

Emerging discipline

Traditional SEO focuses heavily on search engine results pages.

GEO focuses on improving how your content can be discovered, understood, and referenced by AI-powered search and answer systems.

Examples of AI search experiences include:

- Google AI Overviews.
- ChatGPT search.
- Perplexity.
- Microsoft Copilot.

### **Practical GEO strategy**

1. Publish authoritative, accurate content.
2. Answer questions clearly and directly.
3. Include original data, research, and examples.
4. Identify your organization and authors clearly.
5. Use descriptive headings and semantic HTML.
6. Maintain consistent business information.
7. Make important content accessible to crawlers.
8. Earn genuine mentions and references from relevant sources.
9. Keep information accurate and up to date.

You may encounter `llms.txt` files and AI-specific crawler controls. These can be considered as additional experiments, but they are not a guaranteed Google ranking factor or a substitute for standard SEO.

### **Important: Centralized SEO configuration**

Rather than writing everything independently on every page, create reusable SEO utilities.

For example:

```
// lib/seo/metadata.ts

import type { Metadata } from "next";

const siteUrl = "https://www.example.com";

export function createMetadata({
  title,
  description,
  path,
}: {
  title: string;
  description: string;
  path: string;
}): Metadata {
  const canonical = new URL(path, siteUrl).toString();

  return {
    title,
    description,

    alternates: {
      canonical,
    },

    openGraph: {
      title,
      description,
      url: canonical,
      siteName: "Example Website",
      type: "website",
      images: ["/og-image.png"],
    },

    twitter: {
      card: "summary_large_image",
      title,
      description,
      images: ["/og-image.png"],
    },

    robots: {
      index: true,
      follow: true,
    },
  };
}
```

Use it in a page:

```
import { createMetadata } from "@/lib/seo/metadata";

export const metadata = createMetadata({
  title: "Solar Installation in Varanasi",
  description: "Explore solar installation services.",
  path: "/solar-installation-varanasi",
});

export default function Page() {
  return <main>Solar Installation</main>;
}
```

Set `metadataBase` in your root layout if you use relative metadata image URLs:

```
// app/layout.tsx

import type { Metadata } from "next";

export const metadata: Metadata = {
  metadataBase: new URL("https://www.example.com"),

  title: {
    default: "Example Website",
    template: "%s | Example Website",
  },

  description: "Official website description.",

  openGraph: {
    siteName: "Example Website",
    type: "website",
    images: ["/og-image.png"],
  },
};
```

This creates a reusable foundation. Your actual pages should still have unique titles, descriptions, canonical URLs, and appropriate social metadata.

## 2. Next.js SEO Implementation (App Router)

Next.js gives you a strong technical SEO foundation out of the box—especially with Server-Side Rendering (SSR) and Static Site Generation (SSG)—because crawlers receive fully rendered HTML immediately rather than waiting for client-side JavaScript.

### Rendering Strategy

* **SSG (Static Site Generation):** Best for blogs, marketing pages, and docs that don't change on every request. Use `generateStaticParams` to pre-render dynamic routes at build time.
* **SSR (Server-Side Rendering):** Best for frequently updated or personalized pages where fresh HTML is needed on every request.
* **Server Components:** Keep static content in React Server Components to minimize client-side JavaScript, which directly improves Interaction to Next Paint (INP).

### Metadata API & Canonical URLs

Use the built-in Metadata API in `layout.tsx` and `page.tsx` to define unique titles, descriptions, Open Graph tags, and canonical URLs. Always set `metadataBase` in your root layout so relative URLs resolve properly.

```tsx
// app/layout.tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  metadataBase: new URL('https://yourdomain.com'),
  title: {
    default: 'Your Brand',
    template: '%s | Your Brand',
  },
  description: 'Default site description under 160 characters.',
  openGraph: {
    type: 'website',
    siteName: 'Your Brand',
  },
};

```

For dynamic routes, export `generateMetadata` to fetch page-specific titles, descriptions, and canonical links:

```tsx
// app/blog/[slug]/page.tsx
export async function generateMetadata({ params }: { params: { slug: string } }) {
  const post = await getPost(params.slug);
  return {
    title: post.title,
    description: post.excerpt,
    alternates: {
      canonical: `/blog/${params.slug}`,
    },
  };
}

```

### Sitemaps & Robots.txt

Next.js App Router automatically serves `/sitemap.xml` and `/robots.txt` when you add `app/sitemap.ts` and `app/robots.ts`.

* Include only clean, indexable URLs in your sitemap.
* Use `robots.txt` to block admin or private routes, while ensuring you don't accidentally block static assets needed to render the page.
* Use `robots: { index: false }` in metadata for low-value dynamic pages like empty search results or redundant filter combinations.

### Core Web Vitals Optimization

Google uses Core Web Vitals (LCP, INP, CLS) as page experience signals:

* **Images (`next/image`):** Automatically serves modern formats (WebP/AVIF) and prevents Cumulative Layout Shift (CLS) by reserving space with `width` and `height`. Add `priority` to above-the-fold hero images to boost Largest Contentful Paint (LCP).
* **Fonts (`next/font`):** Self-hosts fonts and eliminates layout shift and invisible text during loading.
* **Code Splitting (`next/dynamic`):** Lazy-load heavy client components that aren't needed on initial load.

### Structured Data (JSON-LD)

Add JSON-LD `<script type="application/ld+json">` blocks to help search engines understand your entities and qualify for rich results.

* Place site-wide schema (like `Organization`) in `app/layout.tsx`.
* Place page-specific schema (like `Article`, `Product`, or `FAQPage`) inside the corresponding `page.tsx`.

Once deployed, continuously monitor your site using:

* **Google Search Console:** Submit your `/sitemap.xml`, inspect indexed vs. excluded pages, and check for crawl or canonical errors.
* **PageSpeed Insights / Lighthouse:** Track real-world Core Web Vitals (LCP, INP, CLS) and performance scores.
* **Google Rich Results Test:** Validate your JSON-LD structured data before and after deployments.

## Next.js technical SEO (App Router)

### 1. Pick the right rendering strategy
Search engines index server-rendered HTML best, so use these:
- **SSG** for blogs, docs and marketing pages.
- **ISR** (`revalidate`) for content that changes occasionally.
- **SSR** only for truly dynamic pages.
- Avoid client-only rendering (`useEffect` fetching) for content you want indexed.

### 2. Metadata API
Static:

### 3. Sitemap and robots
```ts
// app/sitemap.ts
import type { MetadataRoute } from "next";

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const posts = await getAllPosts();
  return [
    { url: "https://example.com", lastModified: new Date(), priority: 1 },
    ...posts.map((p) => ({
      url: `https://example.com/blog/${p.slug}`,
      lastModified: p.updatedAt,
    })),
  ];
}
```
```ts
// app/robots.ts
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: { userAgent: "*", allow: "/", disallow: ["/api/", "/admin/"] },
    sitemap: "https://example.com/sitemap.xml",
  };
}
```

### 4. Structured data (JSON-LD)
```tsx
export default function Page() {
  const jsonLd = {
    "@context": "https://schema.org",
    "@type": "Article",
    headline: post.title,
    datePublished: post.date,
    author: { "@type": "Person", name: post.author },
  };
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, "\\u003c") }}
    />
  );
}
```

### 5. Performance and Core Web Vitals
- `next/image` gives automatic sizing, lazy loading, and AVIF/WebP. Add `priority` to the above-the-fold hero image.
- `next/font` avoids layout shift and extra font requests.
- `next/script` with `strategy="lazyOnload"` or `"afterInteractive"` for third-party scripts.
- Use `dynamic()` imports for heavy client components, and keep `"use client"` boundaries small.
- Targets: LCP under 2.5s, INP under 200ms, CLS under 0.1.

### 6. International SEO

- Return real 404s using `notFound()`, not a soft 404 with a 200 status.

- Generate OG images with `opengraph-image.tsx`.
- Use clean, readable URLs (`/blog/nextjs-seo-guide`, not `/p?id=123`).
- Keep dev and staging sites `noindex`.

```tsx
  twitter: { card: 'summary_large_image' },
  robots: { index: true, follow: true },
}
```

**Per-page / dynamic (`generateMetadata`)**:
```tsx
export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { slug } = await params
  const data = await getData(slug)

  return {
    title: data.title,
    description: data.description,
    alternates: {
      canonical: `/blog/${slug}`, // or full URL
      // languages: { 'en': '...', 'es': '...' } for international
    },
    openGraph: {
      title: data.title,
      description: data.description,
      images: [data.ogImage],
      type: 'article',
    },
    robots: data.noIndex ? { index: false } : undefined,
  }
}
```

Always set `metadataBase`. Relative canonical/OG URLs become absolute automatically.

#### Sitemaps & robots.txt
```tsx
// app/sitemap.ts
import type { MetadataRoute } from 'next'

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  // Fetch dynamic routes from CMS/DB
  return [
    { url: 'https://www.yourdomain.com', lastModified: new Date() },
    { url: 'https://www.yourdomain.com/blog/post-1', lastModified: post.updatedAt },
    // ...
  ]
}
```

```tsx
// app/robots.ts
import type { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: '*',
      allow: '/',
      disallow: ['/admin/', '/api/', '/dashboard/'],
    },
    sitemap: 'https://www.yourdomain.com/sitemap.xml',
  }
}
```

Google largely ignores `priority` and `changefreq`. Accurate `lastModified` is useful. Only include indexable, 200-status URLs.

#### Structured Data (JSON-LD)
Render in a Server Component (no official Metadata field for it):
```tsx
<script
  type="application/ld+json"
  dangerouslySetInnerHTML={{
    __html: JSON.stringify({
      '@context': 'https://schema.org',
      '@type': 'Article', // or Organization, Product, FAQPage, etc.
      headline: title,
      // ...
    }).replace(/</g, '\\u003c'), // safety
  }}
/>
```

#### Rendering strategy
- **SSG / ISR** → best for most marketing/content pages (fast + crawlable).
- **SSR** → good for dynamic/personalized pages.
- Avoid pure Client-Side Rendering for public pages (crawlers may see little or “Loading…”).

#### Performance & Core Web Vitals
- Use `next/image` (with proper `width`/`height` or `fill` + `sizes`; `priority`/`preload` for LCP images).
- Use `next/font` for self-hosted fonts (prevents CLS).
- Keep client JS minimal; prefer Server Components.
- Target: LCP < 2.5s, INP < 200ms, CLS < 0.1.

#### Other technical essentials
- One real H1 per page with actual text in the HTML.
- Proper status codes (use `notFound()` for 404s, `permanentRedirect()` for moved pages).
- Consistent trailing slash / www / non-www (redirects + canonicals).
- Open Graph images: static files or dynamic `opengraph-image.tsx` / `ImageResponse`.
- Internal links with `<Link>` (real `<a href>` tags).

### 3. On-Page SEO in Next.js
- Unique, keyword-rich titles (< ~60 characters) and descriptions (~150–160).
- Semantic HTML + proper heading hierarchy.
- High-quality, helpful content that answers search intent.
- Descriptive alt text on images.
- Strong internal linking structure.
- Clean, readable URLs.

### 4. Off-Page, Local, International & Other Types
- **Off-page**: Earn quality backlinks, build brand mentions, encourage reviews.
- **Local**: Optimize Google Business Profile, create location pages, collect reviews, use LocalBusiness schema.
- **International**: Use `alternates.languages` in metadata + consistent URL structure (usually subdirectories like `/en/`, `/es/`). Include hreflang in sitemap when needed.
- **eCommerce**: Product schema, unique product descriptions, optimized category pages.
- **AI / GEO**: Write clear, answer-first content, use schema, ensure content is in the initial HTML (many AI crawlers don’t execute JS well).

### Quick Production Checklist
1. `metadataBase` + title template in root layout.
2. Unique title + description + canonical on every indexable page.
3. `sitemap.ts` + `robots.ts`.
4. JSON-LD where relevant.
5. Content is server-rendered (check page source / `curl`).
6. Core Web Vitals green.
7. Search Console + Bing Webmaster Tools set up and sitemap submitted.
8. Proper redirects and 404 handling.
9. Mobile-friendly + fast.
